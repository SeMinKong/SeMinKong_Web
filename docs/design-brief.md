# Design brief

현재 구현 기준: 2026-09-12. 이 문서는 현재 승인된 디자인만 설명한다. 이전 시안과 변경 과정은 [디자인 이력](history/design-brief.md)에 보관한다.

## 목적과 콘텐츠

공세민의 AI, Robotics, Computer Vision, Software 프로젝트를 실제 구현 근거와 함께 소개한다. 개인 역할, 팀의 성과, 검증 한계를 구분하고 확인되지 않은 수치·성과를 추가하지 않는다. 한국어 설명과 영어 프로젝트·기술명을 함께 사용한다.

- 공개 이름: Se Min Kong. 현재 거주지: Suwon.
- Home: Hero → Projects → Focus → About → Contact.
- Work: THING, AQIS, Brain Tumor MRI, Alkkagi, Briefit, Project Prompt Generator의 여섯 프로젝트. 실제 미디어·프로젝트명·한 문장 설명·상세 링크만 둔다.
- 각 Case study: 역할, 구현, 결과, 근거 링크를 읽을 수 있는 독립 문서.
- About: 소개, 현재 관심, 경험, 기술 도구.
- Resume: 원본 문서 미리보기·다운로드, 수상 증빙 모달, 포트폴리오 PDF 다운로드.
- Copyright: 사용한 자료와 라이선스 범위를 설명한다.

경로와 entry의 기준은 `config/site-routes.js`다. 프로젝트 사실과 자료 출처는 [포트폴리오 근거](portfolio-evidence.md), [시각자료 출처](portfolio-visual-sources.md)를 따른다.

정적 PDF는 9쪽으로 구성한다. 소개·연락처·자격·수상·학력(1) → 구현 경험과 기술 스택(2) → THING·AQIS·Briefit·MRI·Prompt·Alkkagi 각 1쪽(3–8) → 상세 문서 안내와 연락처(9) 순서다. 프로젝트마다 제품 목적, 개인 역할, 실제 이미지, 핵심 구현, 코드로 확인한 설계 선택, 검증 범위를 담는다. 기존 27쪽의 기술 해설·계산식·도식·예외 처리는 각 프로젝트 README와 링크된 상세 문서에 보존한다. 원본 구조도·실제 미디어·수상 자료는 기존 자산과 웹 상세에서 유지한다. [이전 내용의 위치와 반영 커밋](portfolio-migration.md)을 기준으로 한다.

PDF의 각 프로젝트는 README·상세 구현 문서·웹 사례에 직접 연결하며 마지막 쪽에서도 문서 링크를 다시 찾을 수 있다. README는 역할·핵심 구현·실행 방법을 먼저 제공하고 상세 문서는 방법·계산·상태 전이·예외·고정 소스 근거를 설명한다. 개인/팀 기여, 설정/실측, 코드/시연의 범위를 구분한다. 확인되지 않은 숙련도 점수나 복원한 실패담을 추가하지 않는다. 본문 최소 9pt를 유지한다.

AQIS 저장소의 상세 기술 문서와 웹 사례는 실제 검사·분류, RoboDK 가상 공정, TurtleBot SLAM·로봇 관제를 다룬다. 웹은 실제 공개 시연 영상과 명령/상태 흐름, PDF 4쪽은 실제 관제 프레임과 핵심 연결 원리를 요약한다. RoboDK UR5 공정과 실제 Dobot URDF 관절 표시를 구분한다. 지도는 RViz에서 시각화하며 React는 지도 갱신 시각·위치·카메라를 관제한다. 자체 SLAM 알고리즘이나 Nav2 자동 임무 완료로 확대하지 않는다. 사용자 재생형 영상, 기존 공통 motion/media lifecycle과 반응형 구조를 사용한다.

## 읽기 편한 비율과 표현

항상 눈이 편한 비율·정렬·여백을 먼저 확인한다. 내용을 더 넣기 위해 글자를 줄이거나 장식과 강조를 늘리지 않는다. 설명은 구체적인 입력·방법·조건·결과를 쓰며 추상적인 홍보 표현과 반복된 해설을 줄인다. THING·AQIS 수준의 근거와 구성은 참고하되, 프로젝트마다 확인할 수 있는 깊이에 맞춘다.

- PDF는 A4 가로·38pt 여백과 좌측 이미지/역할·우측 구현 설명을 사용한다. 제목·본문·검증 범위의 위계를 유지하고 한글 단어 중간 줄바꿈을 피한다. 모든 본문과 링크는 최소 9pt다.
- 도식 상자 안의 짧은 제목·보조 문구와 그림별 라벨은 중앙정렬한다. 그림도 라벨과 같은 중심축에 맞춘다. 사진 캡션은 실제로 배치한 이미지 폭을 기준으로 중앙정렬하고 이미지 아래 간격을 10pt로 맞춘다. 그래프 눈금·막대 값·상태점의 짧은 표기는 각 기준점에 중심을 맞춘다. 긴 문단과 여러 줄 수식은 왼쪽 정렬을 유지한다. 화살표가 순서를 나타내는 곳의 단계 숫자와 기술 페이지의 편집용 번호는 생략한다. 계산값·조건값·쪽수·원본 자료의 숫자는 유지한다.
- 같은 행의 흐름 상자는 높이와 간격을 맞춘다. 연결선은 상자 중심에 연결하고 양끝 여백은 6pt로 맞춘다. 화살표와 문자가 닿지 않게 하며 수식은 짙은 회색, 핵심 수치에만 강조색을 쓴다.
- 웹은 소개·기존 미디어를 보존하고 원본 아키텍처, 세 가지 핵심 구현, 소스 링크를 연결한다. 기술 본문은 넓은 열과 1.85 줄 간격을 사용하며 작은 화면에서 한 열로 쌓는다. 원본 구조도는 비율을 유지하고 원본 크기 링크를 제공한다.
- 매 PDF 변경에서 전체 렌더와 화살표·본문 겹침을 확인한다. 웹은 390·768·1280px에서 긴 설명·수식·도식·키보드 이동을 확인한다.

PDF 2쪽의 기술 스택은 사용 도구와 학습 관심을 다섯 분야의 텍스트 목록으로 간결하게 보여준다. dev에서 정리한 16개 도구를 사용하되 숙련도 별점·백분율을 넣지 않는다. 웹의 기존 스택은 이번 PDF 편집에서 변경하지 않는다. About은 최신 main의 16개 도구와 별점 표시, Resume는 기존 13개 학습 도구를 유지한다. 웹의 두 목록을 다시 통일하거나 별점 기준을 정하는 일은 별도 범위다. 웹 언어 아이콘 96px(700px 이하 80px)·분야 아이콘 56px, 섹션 패딩 24px·제목 아래 12px·카드 행 간격 8px을 유지한다. 작은 화면은 분야를 한 열로 쌓고 한 화면 맞춤을 강제하지 않는다.

웹 스택의 실제 항목은 각 페이지 markup을 기준으로 한다. 웹의 아이콘은 native details/summary로 클릭·터치·Enter·Space를 통해 이름만 열고 닫을 수 있다. summary의 접근 가능한 이름과 브라우저 기본 title을 제공하며 JavaScript 없이 동작한다. 이름 영역은 미리 확보해 펼쳐도 아이콘·다음 분야가 움직이지 않는다. 공통 스택의 프로젝트 링크·성과 설명과 중복 도구 펼침 목록은 제거한다. 짧은 분야명·비교 상자·캡션은 중앙정렬하고 긴 프로젝트 설명은 왼쪽 정렬한다. 각 분야의 도구는 가용 폭 안에서 중앙 배치하고 모바일의 분야는 1열로 쌓는다. AQIS 명령/반환 도식은 기존 공통 행 높이를 유지한다.

## 시각 언어

따뜻한 종이색, 짙은 graphite, 제한적인 vermilion을 사용한다. 배경의 wash와 grain은 정적이며, 실제 프로젝트 이미지와 영상의 원래 비율을 보존한다. 과장된 HUD, 기술 점수, 장식용 상태 표시를 추가하지 않는다.

제목과 표시용 텍스트의 Latin·숫자는 Signika Variable, 한글은 Jua를 사용한다. 긴 본문은 `--font-body`의 시스템 sans-serif를 사용하며 세부 UI 적용은 토큰과 CSS를 따른다. Jua의 가짜 굵기는 만들지 않는다. Manrope는 Hero 서명의 투명한 크기 측정 텍스트에만 필요하다. 폰트는 npm 패키지의 파일을 자체 호스팅한다.

디자인 토큰은 `src/styles/tokens.css`, 공통 UI는 `base.css`, 전역 종이 표면은 `gallery-surface.css`가 소유한다. 실제 수치와 반응형 규칙은 해당 CSS가 기준이다.

## Home Hero

- 이름은 기존 12개 SVG 획의 서명을 사용한다.
- 인사말은 “안녕하세요!”와 “새로운 것을 배우고 직접 만드는 일이 즐겁습니다.”다.
- 주요 행동은 Work로 이어지는 “프로젝트”와 Home Contact로 이어지는 “Contact”다.
- 첫 화면은 100svh를 기본으로 하며 작은 화면에는 읽기에 필요한 최소 높이를 유지한다.
- 텍스트와 링크는 semantic HTML로 즉시 제공한다. 캔버스가 준비되지 않거나 모션이 줄어도 접근 가능해야 한다.
- 별도 인트로 overlay, 화면 잠금, 스크롤 안내, Motion/Depth 수동 스위치를 만들지 않는다.

## 연구용 로봇 키트

7종 SVG를 11개 조각에 재사용한다. 단일 센서 머리, 넓은 분할 흉곽, 골반, 내부가 열린 상완, 집게가 있는 전완, 넓은 대퇴, 발판이 있는 하퇴로 기능과 외곽선을 구분한다.

색은 shell `#DED6CA`, graphite `#24211D`, metal `#B8AFA2`, sparse vermilion `#A73524`다. 2~3단계 얕은 bevel, 얇은 이음선, 부품 내부의 bearing을 사용한다. 얼굴·두 눈·문자·HUD·neon·무작위 vent/볼트는 넣지 않는다.

`robot-kit.js`의 SVG 치수와 bearing 중심이 물리 관절과 정적 완성형의 기준이다. 그림자도 같은 SVG의 alpha 형태를 사용해 열린 프레임과 집게 틈을 보존한다.

- 데스크톱 약 2배, 태블릿 약 1.75배, 모바일 약 1.55배로 표시한다.
- 모바일·태블릿의 초기 배치는 이름·설명·CTA 주변을 비운다.
- 부품은 사용자가 움직일 수 있고 텍스트 위를 지나갈 수 있다. 읽기·클릭·키보드 접근은 DOM이 소유한다.
- 가까운 호환 연결부와 회전할 관절에만 얇은 ring을 표시한다.
- 조립은 마우스 35°·터치 40°까지 각도 오차를 허용한다. 가까운 연결부에 잠깐 머무르거나 부품을 놓으면 180ms 동안 위치와 각도가 맞춰진다. 연결부 사이의 흐린 곡선 하나와 결합 후 작은 ring 한 번으로 반응을 표현한다. 기존 붉은 강조색과 재질을 유지한다.
- Reduced/forced-colors는 완성된 정적 로봇을 제공한다. 작은 화면에서는 이름 위 우측 여백에 둔다.

세부 동작은 [모션 명세](motion-spec.md)에 정의한다.

## 개인정보와 원본 자료

웹의 일반 markup에는 전화번호·생년월일·증명사진을 추가하지 않는다. 이미 승인된 원본 Resume 파일과 포트폴리오 PDF는 예외이며 기존 다운로드를 유지한다. PDF 전용 증명사진 원본은 `.private/`에 두고 별도 웹 자산으로 공개하지 않는다.

원본 사진·영상·상장과 실제 작업 자산을 임의로 삭제하거나 다시 그리지 않는다. 정적 PDF 변경은 재생성·렌더 검수·공개 사본과 용량/날짜/해시 동기화가 필요하다.
