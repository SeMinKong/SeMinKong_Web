# Current decisions

현재 유효한 결정과 새 변경만 기록한다. 2026-09-07까지의 전체 승인·변경 기록은 [결정 이력](history/decisions.md)에 보관한다.

## 2026-09-08 — 기술 도식 시각화와 AQIS 범위 확장

- 사용자가 기술 설명을 PPT처럼 직관적으로 시각화하고 웹/PDF 모두 AQIS digital twin·TurtleBot SLAM을 보강하는 방향을 승인했다. 기존 기술 도식 6쪽은 그래프·시간축·토큰 띠·변환/상태/충돌 그림으로 재구성하고 계산식·조건을 함께 둔다.
- AQIS에 RoboDK 공정 연결과 SLAM/관절 관제 두 쪽을 추가해 총 26쪽으로 구성한다. 프로젝트 순서·소개 시작·기존 구조도·수상 자료는 유지한다. 새 목차, PDF 검증/다운로드 계약, 원본 PNG 목적 쪽번호를 맞춘다.
- AQIS 공개 GitHub 소스 60951747과 공개 10초 시연 GIF/PNG만 사용한다. 웹 영상은 GIF를 사용자 재생형 H.264로 변환한다. 내부 원본 영상은 사용하지 않는다.
- RoboDK UR5 가상 공정은 팀원 담당, RealOps·서버·ROS bridge·URDF 관제는 본인 범위다. RViz 지도와 React 상태 표시, RoboDK 시뮬레이션과 실제 Dobot 관절 뷰를 구분한다. Nav2 자동 임무·실측 성능을 추가 성과로 주장하지 않는다.
- 검증 후 기존 GitHub Pages에 배포한다. 별도 아키텍처 SVG/아이콘 초안은 이번 공개 범위에서 제외한다.

## 2026-09-08 — 기존 내용 보존과 기술 도식 추가

- 사용자가 기존 설명을 없애지 않고 추가하라고 명확히 요청했다. 앞선 기술 페이지 교체안 대신 기존 18쪽을 보존하고 프로젝트마다 기술 도식 한 쪽을 추가해 총 24쪽으로 구성한다.
- 프로젝트 순서는 THING → AQIS → Briefit → MRI → Prompt → Alkkagi, 각 프로젝트는 소개부터 시작한다. 기존 기술 설명 다음의 5·10·14·17·20·23쪽에 새 도식을 배치한다. 목차 범위와 북마크·PNG 배치 계약을 동기화한다.
- 새 페이지는 코드 기반 처리 흐름·상태 전이·단위 변환·충돌 수식과 의사코드를 보여준다. 기존 로고 구조도·본문·실제 미디어·수상 자료는 그대로 둔다. 의사코드와 개념도는 실제 실행 결과와 구분한다.
- PDF 원본·공개 사본·Resume의 24쪽/용량/2026.09.08 표시·해시를 맞춘 후 기존 Pages pipeline으로 배포한다. 별도 작업 중인 아키텍처 SVG·아이콘 변경은 제외한다.

## 2026-09-07 — 프로젝트별 소스 기반 기술 해설

- 사용자가 GitHub 소스를 참고해 프로젝트마다 기술 페이지 한 쪽을 배정하는 방향을 승인했다. 기존 구조도 페이지 4·8·11·13·15·17쪽을 재편하고 18쪽 분량·프로젝트 순서·소개 시작은 유지한다.
- THING은 landmark → 7축 목표 → 명령 검사 → 모터 구동, AQIS는 깊이 역투영 → 검출 정규화 → 장비 좌표, Briefit은 KoBART 입력/정답 구성 → 생성·재요약, MRI는 학습 라벨 변환과 독립 추론, Prompt는 문맥·상태·문서 합성, Alkkagi는 입력 제한과 충돌·마찰 계산을 설명한다.
- 원본 구조도는 픽셀·alpha·비율을 유지해 배치한다. 3개 기술 단락과 입력/출력 흐름, 짧은 담당·검증 범위, commit에 고정한 소스 링크를 공통 형식으로 사용한다.
- 팀 알고리즘을 개인 기여로 확대하지 않는다. Prompt의 합성은 결과가 있는 일부 영역만으로도 가능하다. Briefit 학습 완료·생성 품질과 MRI 독립 성능, 실물·부하 수치를 새 성과로 주장하지 않는다.

## 구현과 배포 기준

- Vite 다중 페이지와 npm을 유지한다. 11개 route는 `config/site-routes.js`가 관리한다.
- 페이지별 entry와 CSS를 유지하고 공통 lifecycle은 `create-page-runtime.js`에 등록한다. 새 프레임워크나 모션 라이브러리 전면 이관은 하지 않는다.
- Anime.js를 기본으로 사용하고 Work/THING의 scrubbed story만 GSAP으로 구현한다. Three.js 대신 현재 Pixi/Matter와 얕은 SVG/그림자를 유지한다.
- 현재 디자인과 기능은 [디자인 명세](design-brief.md), [모션 명세](motion-spec.md)를 따른다.
- 2026-09-04 상시 사용자 지침: 승인된 웹·정적 PDF 변경은 검증 후 기존 GitHub Pages에 배포한다. 필요한 범위의 commit/push를 포함한다. 로컬 전용·배포 보류 등 이후 명시 지시가 우선한다.
- 공개 대상은 검수한 변경뿐이다. 별도 작업 중인 수정, 비공개 원본, 임시 생성물, scratch는 포함하지 않는다. 배포 파이프라인 성공과 실제 페이지 확인 전에는 완료로 보고하지 않는다.
- PDF 변경은 원본 재생성·렌더 검수·public 사본 및 용량/날짜/해시 동기화를 함께 수행한다. 웹 빌드만 할 때는 이미 검수한 public PDF를 그대로 사용한다.
- PDF용 사진 원본은 `.private/`에 둔다. 공개 Resume와 포트폴리오에 대한 기존 승인 범위는 유지한다.

## 2026-09-07 — 핵심 구현 중심 저장소 정리

사용자가 불필요한 파일을 제거하고 핵심 구현을 읽기 쉽게 리팩토링하도록 요청했다. 시각 결과·입력·접근성·라우팅·공개 다운로드를 보존한다.

- 사용 경로가 없는 Hero scroll module과 중복 clamp utility, 폐기된 overlay wordmark builder를 삭제한다.
- Home의 서명/Hero/로봇 스타일은 `kinetic-home.css`, Projects 이하와 Home 전용 navigation은 `home.css`가 소유한다. 주석 처리된 Signal Lab 시안과 실제로 덮어쓰이는 옛 규칙을 제거한다.
- 로봇 설정, artwork/hint, 완성 pose/effect를 명시적인 모듈로 나눈다. Gesture와 joint physics는 공유 상태가 밀접하므로 runtime 안에 유지한다. 기존 facade와 lazy import 경로는 유지한다.
- 변수명·선언 위치를 반복 검사하던 source 검증 대신 entry→module import graph의 도달 가능성과 route/CSS 경계를 검사한다. 수학·관절 정렬·lifecycle 동작 테스트와 public artifact 검증은 유지한다.
- 현재 연결된 Sites 프로젝트는 조회 결과 NOT_FOUND였고 기존 배포는 GitHub Pages만 사용한다. 미사용 `.openai/hosting.json`과 public Worker adapter를 제거한다. 사이트나 공유 설정을 새로 만들거나 변경하지 않는다.
- 모든 선언된 npm dependency는 실제로 사용되어 유지한다. 실제 이미지·영상·문서·PDF 제작 소스도 보존한다.
- 오래된 승인/검수 기록은 `docs/history/`에 보관하고 현재 명세는 짧고 일관되게 다시 정리한다. `tmp/`는 Git에서 제외한다.

## 2026-09-07 — 실무 판단과 검증 범위 중심 정적 포트폴리오

사용자가 모터 응답 개수·소규모 테스트·호출 1회 제거 등 사소한 수치를 대표 성과로 쓰지 않고, 시스템 신뢰성·실물 편차 대응·출력 품질에 집중하는 방향을 승인했다.

- PDF는 20→18쪽으로 줄이고 AQIS를 첫 사례로 배치한다. AQIS 4쪽, THING 4쪽, Briefit 2쪽, MRI 2쪽, Alkkagi·Prompt 각각 1쪽으로 정리한다. 소개·교육·목차·연락처와 수상 4건을 유지한다.
- AQIS에는 초기 장비 사용 제약, 정지 요청 뒤 좌표 재취득, 중복·정지 상태·timestamp가 있는 오래된 입력의 검증 범위를 설명한다. 정지 센서 확인·파지 성공 확인·장애 복구를 구현 성과로 확대하지 않는다. 기존 좌표 변환 기대값 불일치를 남은 문제로 표시한다.
- THING은 장력·권취 방향, 초기 목표 설정과 토크 인가 순서, 원위치 선택·정지 경로와 재장착 기록을 연결한다. 간섭·강도·축별 끝점 보정이 완료됐다고 쓰지 않는다. 팀 안전 제어기 전체는 개인 기여에서 제외한다.
- Briefit은 입력 필터, 반복 끝문장 제거와 정상 정보 손실 가능성, 후처리 전 ROUGE 평가의 범위를 설명한다. 합성 문장·마스크 전용 페이지와 Alkkagi 조작법 페이지는 제거한다. 데이터 분할은 보조 정보로만 남긴다.
- 새 실물·모델·부하 실험은 실행하지 않았고 미측정 수치와 실험 계획을 공개 성과에 넣지 않는다. 기존 Mock 재현은 당시 개인/팀의 실물 시험과 구분한다.
- 기존 원본 PNG 5개의 픽셀·알파·해시는 유지하며 배치 쪽수만 동기화한다. 별도 진행 중인 아키텍처 SVG·아이콘 변경은 이 릴리스에 포함하지 않는다.
- 다운로드가 있는 Resume 화면도 같은 근거 기준으로 맞춘다. MRI의 근거 미확인 점수, Alkkagi의 실측처럼 읽히는 FPS, 개인 근거가 확인되지 않은 Briefit grouping 귀속을 수정한다. 다른 Case study의 전체 개편은 이 PDF 작업에 포함하지 않는다.

## 2026-09-07 — 프로젝트 순서와 소개 페이지 통일

- 사용자가 THING → AQIS → Briefit → MRI → Prompt → Alkkagi 순서와 프로젝트별 소개 페이지 시작을 요청했다. 위 18쪽 편집안의 순서·분량 결정을 대체한다.
- THING 4–7쪽, AQIS 8–11쪽, Briefit 12–13쪽, MRI 14–15쪽, Prompt 16–17쪽, Alkkagi 18–19쪽으로 배치하고 연락처는 20쪽에 둔다. 목차 링크는 각 소개 페이지를 가리킨다.
- Prompt와 Alkkagi에 개요·기간·담당 역할·사용 기술을 담은 소개 페이지를 추가한다. 원본 설계 흐름도와 실제 게임 영상 프레임을 사용하며 구현 구조는 다음 쪽에 둔다.
- 기존 17개 비목차 페이지의 본문은 쪽번호 외 변경 없이 유지한다. 새 측정 결과·추정 성과·조작법 전용 페이지는 추가하지 않는다. 기존 원본 구조도 5개도 그대로 유지한다.

## 2026-09-07 — 간결한 소개와 구현 판단 중심 편집

- 사용자가 중요도가 낮은 내용을 분석한 결과에 동의하고, 간결하지만 밀도 있는 내용으로 수정·보강하며 이미지 설명을 줄이도록 요청했다.
- 기존 프로젝트 순서와 여섯 소개 페이지를 유지한다. 독립 학력·관심사 페이지를 첫 소개와 온라인 이력서로 정리하고 AQIS 좌표 갱신·검증표를 통합해 20→18쪽으로 줄인다. 위 20쪽 분량·본문 유지 결정을 대체한다.
- THING 3–6쪽, AQIS 7–9쪽, Briefit 10–11쪽, MRI 12–13쪽, Prompt 14–15쪽, Alkkagi 16–17쪽, 연락처 18쪽으로 배치한다.
- 이미지의 번호 안내·긴 캡션, 반복된 담당 범위·구조 설명, Briefit 필드명·분할 건수를 걷어낸다. 소개는 제품 목적과 역할, 상세는 구체적인 구현 선택을 설명한다.
- 개인 원본 코드로 확인된 Briefit 부분 요약·재요약, MRI 외부 윤곽 변환과 독립 추론, Prompt 완료 조건·호출 오류 처리, Alkkagi 겹침·충격량·소단계 마찰 계산을 보강한다. 측정 성과나 당시 개인의 동기로 확대하지 않는다.
- 실제 정지·파지 성공 확인 부재, 평가 데이터 독립성, 영속성 등 해석에 필요한 한계는 남긴다. 원본 이미지와 구조도 PNG 5개는 변경하지 않고, 수상 4건과 근거 링크를 유지한다.

## 2026-09-08 — 계산과 실행 조건을 설명하는 기술 6쪽

- 사용자는 단순한 처리 흐름보다 어떤 방법으로 무엇을 해결했는지를 요청했다. 추가된 5·10·14·17·20·23쪽을 프로젝트당 세 가지 구현 방법으로 재작성한다. 기존 18쪽·소개 시작·프로젝트 순서·원본 이미지·수상 증빙은 그대로 유지한다.
- 왼쪽 설명과 오른쪽 계산식·설정·의사코드를 대응시키며 본문은 10.2pt를 유지한다. THING 관절 기하·입력 필터·엔코더 보간·엄지 전이·20Hz/50Hz 분리를 기준 깊이로 삼는다.
- 활성 YAML, 원본 구현 분기와 단위를 확인한다. 팀 ROS 운영 제어를 본인 구현으로 돌리지 않고, 설정 주기·계산 예시·실측 결과를 구분한다. AQIS timestamp는 촬영 시각이 아닌 이벤트 timestamp이며, Briefit의 학습/생성/평가 토큰 한도도 분리한다.
- 이번 작업은 PDF 기술 설명 6쪽과 다운로드 안내의 개선이다. 별도로 남아 있는 architecture SVG·Excalidraw·아이콘 변경은 포함하지 않는다.


## 2026-09-08 — 편안한 비율과 웹 기술 설명 통일

사용자는 정적 포트폴리오의 내용은 유지하면서 비율·정렬·여백과 자연스러운 문장을 개선하고, 나머지 웹 프로젝트도 THING·AQIS처럼 근거 있는 기술 설명을 갖추도록 요청했다. 눈에 편안한 구성은 이후 작업에도 적용한다.

- PDF 26쪽·프로젝트 순서·소개 시작·원본 자료는 보존한다. 제목을 23pt로 낮추고 아키텍처 설명 열을 넓힌다. 수식의 굵기·색을 낮추고 도식별 상자 높이·중심선·화살표 끝 여백을 맞춘다. 모호한 제목과 반복된 설명을 구체적인 구현 용어로 바꾼다.
- 제작 스크립트는 연결선을 기록하고, 검증 스크립트는 화살표와 문자의 간섭 및 중심 연결·양끝 6pt 간격을 검사한다. 육안 검수는 계속 수행한다.
- Briefit·MRI·Prompt·Alkkagi 웹에 원본 구조도와 프로젝트별 핵심 구현 세 가지를 추가한다. 기존 소개·영상·이미지를 유지한다. 각 기술은 고정 commit 소스로 연결하며 오류 처리·평가 분리·설정 주기 등 해석에 필요한 조건을 함께 쓴다. THING·AQIS는 문장과 연결선만 소폭 다듬는다.
- 새 웹 구조도 네 개는 승인된 원본 PNG를 lossless WebP로 변환하며 RGBA 픽셀을 보존한다. 별도 진행 중인 SVG·Excalidraw·아이콘 작업은 이번 릴리스에 포함하지 않는다.
- 새 성능 실험이나 하드웨어 시험은 하지 않았다. 모션 라이브러리·동작은 변경하지 않는다. 검증 후 기존 GitHub Pages pipeline으로 웹과 동일한 최종 PDF를 배포한다.


## 2026-09-08 — 도식 문구의 중앙정렬과 단계 번호 생략

- 사용자가 정적 PDF의 왼쪽 쏠림을 지적하고 중앙정렬 및 화살표로 대체되는 단계 번호의 생략을 요청했다.
- 도식 상자 제목·짧은 설명, 토큰 띠·MRI 마스크·윤곽·Prompt 영역 라벨을 각 도형 중앙에 놓는다. 설명이 없는 MRI 상자는 세로 중앙도 맞춘다. Alkkagi의 입력 벡터는 기존 방향·길이 비율을 보존하며 제목과 같은 중심축으로 옮긴다.
