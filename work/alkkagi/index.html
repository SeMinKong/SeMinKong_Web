전통 알까기를 브라우저의 실시간 아레나 게임으로 만들었습니다. 돌을 드래그해 튕기고 상대를 보드 밖으로 밀어내면 점수가 오르며, 돌의 반경과 질량이 달라집니다.

React·TypeScript 화면, Node.js 서버와 Socket.io 통신, 원형 돌에 맞춘 물리 모듈을 직접 구현했습니다. 보드 크기는 접속 인원에 따라 조정합니다.

01 / Authoritative server

클라이언트는 입력을 보내고
서버가 상태를 결정

서버는 입력을 보낸 접속자의 돌을 찾고, 500ms 안의 재입력을 거절합니다. 튕기기 벡터의 크기를 보드 크기에 비례한 상한으로 제한한 뒤 질량으로 나눠 속도를 정합니다.

게임 상태는 서버 메모리에 한 벌로 두고 gameStateUpdate로 배포합니다. React 클라이언트는 받은 위치를 DOM·SVG에 표시하므로 플레이어마다 충돌을 별도로 판정하지 않습니다.

  1. flick 입력접속자 · 재입력 간격 확인
  2. 서버 물리 계산힘 제한 · 질량 반영
  3. 상태 배포모든 클라이언트에 같은 결과

02 / Circle collision

겹친 위치를 먼저 풀고
접근 중일 때 충격량 적용

두 돌의 중심 거리와 반경 합으로 겹침을 찾습니다. 겹친 거리의 절반씩 양쪽 위치를 밀어낸 다음, 두 돌을 잇는 방향의 상대 속도를 확인합니다. 이미 멀어지는 중이면 충격량을 더하지 않습니다.

접근 중이면 반발계수 0.7과 두 돌의 역질량으로 충격량을 계산합니다. 위치 보정은 반씩 나누지만 속도 변화는 질량에 따라 달라져, 커진 돌의 무게가 충돌 반응에 반영됩니다.

n = (p₂ − p₁) / distancevₙ = (v₂ − v₁) · nj = −(1 + 0.7) × vₙ / (1/m₁ + 1/m₂)

중심이 서로 다른 두 돌의 충돌식 · vₙ > 0이면 충격량 계산 생략

03 / Physics update

한 번의 갱신을
10개 소단계로 나누기

서버 타이머는 60Hz를 목표로 설정하고 한 번의 갱신에서 물리를 10회 계산합니다. 각 소단계에서 이동·마찰·충돌·보드 이탈을 처리한 뒤 최종 상태를 배포합니다. 득점과 재배치, 반경·질량 변경도 서버에서 처리합니다.

  1. 소단계 × 10이동 → 감속 → 충돌 → 득점
  2. 게임 상태 갱신반경·질량 · 재배치
  3. gameStateUpdate한 갱신의 결과를 배포
position += velocity × 0.1velocity *= 0.8 ** 0.1
마찰·정지 처리 ↗갱신 루프와 배포 ↗

게임에 필요한 물리

범용 엔진 대신 원형 충돌과 보드 밖 득점에 집중한 TypeScript 모듈로 계산을 구성했습니다. 마찰은 소단계마다 FRICTION ** stepFactor로 적용합니다. 충돌·정지·재배치가 없으면 10회 적용 후 속도는 기존의 0.8배가 됩니다. 각 소단계에서 축별 속도의 절댓값이 0.1 미만이면 0으로 처리합니다.

60Hz는 타이머 설정입니다. 지속 FPS·네트워크 지연·동시 접속 성능은 별도로 측정하지 않았습니다.
