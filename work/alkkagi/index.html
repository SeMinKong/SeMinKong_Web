게임 규칙과 구현

돌을 드래그해 상대를 보드 밖으로 밀어내면 점수가 오르고 돌의 반경과 질량이 커집니다.

React 화면과 Node.js 서버를 Socket.io로 연결하고 원형 충돌 모듈을 직접 구현했습니다. 보드 크기는 접속 인원에 맞춰 조정됩니다.

입력 검증과 서버 상태

플레이어가 돌을 튕기면 서버가 500ms 쿨타임을 먼저 검사하고, 보드 크기에 비례한 최대 힘 상한과 돌의 질량을 반영해 초기 속도를 계산합니다.

모든 물리 상태는 서버 메모리 한 곳에서 관리해 gameStateUpdate로 브로드캐스트하고, React 클라이언트는 받은 좌표를 DOM·SVG로 렌더링하는 역할만 맡겨 클라이언트 간 판정 불일치를 없앴습니다.

  1. flick 입력플레이어 · 쿨타임 확인
  2. 서버 물리 계산힘 제한 · 질량 반영
  3. 상태 배포모든 클라이언트에 같은 결과

원형 충돌과 위치 보정

두 돌이 겹치면 먼저 겹친 거리의 절반씩 양쪽으로 밀어내 위치를 보정하고, 서로 가까워지는 방향일 때만 반발계수 0.7과 역질량 비율로 충격량을 계산합니다.

위치 보정은 동일하게 나누되 속도 변화에는 질량을 반영해, 점수가 올라 커진 돌일수록 묵직하게 부딪히도록 만들었습니다.

n = (p₂ − p₁) / distancevₙ = (v₂ − v₁) · nj = −(1 + 0.7) × vₙ / (1/m₁ + 1/m₂)

중심이 서로 다른 두 돌의 충돌식 · vₙ > 0이면 충격량 계산 생략

갱신당 10회 물리 계산

서버 틱을 60Hz로 두고, 한 틱 안에서 물리를 10개 서브스텝으로 쪼개 계산해 빠른 돌이 서로 통과하는 현상을 줄였습니다. 매 서브스텝마다 이동·마찰·충돌·보드 이탈을 처리하고, 득점에 따른 돌 크기·질량 변화와 재배치까지 반영한 최종 상태를 클라이언트에 보냅니다.

  1. 서브스텝 × 10이동 → 감속 → 충돌 → 득점
  2. 게임 상태 갱신반경·질량 · 재배치
  3. gameStateUpdate한 틱의 최종 상태 배포

게임에 필요한 물리

범용 물리 엔진을 붙이는 대신 원형 충돌과 보드 이탈 판정에 필요한 계산만 TypeScript 모듈로 직접 짰습니다. 마찰은 서브스텝마다 FRICTION ** stepFactor로 분할 적용해 1틱당 속도가 0.8배로 줄어들게 맞췄고, 축별 속도가 0.1 미만으로 떨어지면 완전히 정지시켜 미세한 미끄러짐을 막았습니다.

60Hz 타이머 기준으로 구현했으며, 다수 동시 접속이나 네트워크 지연에 따른 부하 테스트는 아직 진행하지 않았습니다.
