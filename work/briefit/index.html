Briefit은 여러 매체의 기사를 모으고 같은 이슈를 묶어 읽는 팀 뉴스 서비스입니다. 저는 AI 파트에서 약 4,000건의 기사 수집·정제, 약 3,000건의 KoBART 파인튜닝과 T5·KoBART의 ROUGE-1·2 비교를 진행했습니다. 실사용 품질을 보완하기 위해 Gemini API도 연결했습니다.

제품 화면은 팀 결과물이며, 아래 기술 설명과 구조도는 그중 공개된 2025년 KoBART 구현을 다룹니다. 현재 팀의 GPT-OSS 경로와는 구분합니다.

01 / Collection

본문 확보·데이터 정제

기사 본문을 직접 확보하고 모델 입력에 맞게 정제하기 위해 Crawl4AI를 선택했습니다. 수집 대상을 기사 URL로 좁히고 댓글 페이지를 제외했습니다. 본문 선택자를 순서대로 확인해 script·style 등의 요소를 제거한 뒤 텍스트만 JSON으로 저장합니다.

저장에 성공한 URL은 배치 사이에서 공유하는 집합에 넣습니다. 다음 배치가 같은 링크를 만나면 건너뛰므로 한 번의 실행 안에서 중복 저장을 막습니다.

  1. 기사 URL 선택기사 패턴 허용 · 댓글 제외
  2. 본문 정제본문 요소 추출 · 불필요 태그 제거
  3. JSON 저장저장 성공 URL을 집합에 추가
crawl_naver · 수집과 중복 처리 ↗

03 / Long articles

긴 기사는 부분 요약을 모아
다시 요약

생성 단계에서는 입력이 1,024토큰 이하면 한 번에 요약합니다. 더 긴 기사는 문단을 누적해 나누고, 각 부분의 요약문을 연결한 뒤 다시 요약합니다. 부분 요약과 재요약의 출력 상한은 각각 512토큰이며, 생성에는 beam 4개와 length penalty 1.2를 사용합니다.

매 생성 뒤 _clean_tail이 짧은 끝문장과 직전 문장의 반복을 제거합니다. 문단을 더한 뒤 길이를 검사하고 매 입력을 1,024토큰에서 자르므로, 긴 문단이나 연결된 요약문은 일부가 잘릴 수 있습니다.

  1. 문단 묶음입력 길이 검사
  2. 부분 요약각 결과를 줄바꿈으로 연결
  3. 재요약연결된 요약을 새 입력으로 사용

품질을 확인하는 기준

별도 평가 스크립트는 모델의 후처리 전 요약문을 정답 요약과 ROUGE로 비교합니다. 부분·재요약이나 후처리를 거친 최종 출력과는 평가 대상이 다릅니다.

짧은 정상 문장도 후처리에서 지워질 수 있어 자연스러움과 정보 보존을 함께 확인해야 합니다. 약 3,000건의 파인튜닝과 모델 비교는 당시 작업 경험입니다. 공개 저장소에는 해당 체크포인트와 연결된 평가 로그·품질 비교 수치가 포함되어 있지 않습니다.
