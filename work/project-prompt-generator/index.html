01 / Conversation context

여섯 대화의 문맥을
섞지 않고 이어가기

모델 호출마다 영역별 지침, 프로젝트 설명, 해당 영역의 대화 이력, 새 사용자 입력을 구성합니다. 다른 영역의 이력은 포함하지 않아 API를 논의하던 대화가 UI 질문과 섞이지 않게 했습니다.

첫 질문은 asyncio.gather로 함께 시작합니다. 동기식 LLM 호출은 asyncio.to_thread에서 실행하고, 질문과 진행 상태를 WebSocket으로 전달합니다.

02 / Completion condition

대화 횟수와 완료 신호를
함께 확인

입력을 처리할 때 상태를 in_progress로 바꾸고 라운드를 증가시킵니다. 첫 질문도 한 라운드로 셉니다. 3라운드 이상이고 응답에 [GENERATE_PROMPT]가 있어야 결과를 저장하고 completed로 바꿉니다. 세 번을 대화의 상한으로 제한하지는 않습니다.

RuntimeError·ValueError·OSError를 처리할 때는 라운드를 되돌리고 pending으로 복구합니다. 성공한 대화만 이력에 추가하므로 실패한 응답이 다음 질문의 문맥에 들어가지 않습니다.

  1. pending입력 대기
  2. in_progressround + 1 · 모델 호출
  3. completedround ≥ 3 + 완료 태그

미완료 응답 → in_progress 유지 · 처리 대상 오류 → pending·이전 라운드

03 / Document output

작성된 영역부터
하나의 문서로 모으기

최종 문서 요청은 저장된 generated_prompt가 있는 영역을 모아 프로젝트 설명과 함께 별도의 모델 호출에 전달합니다. 여섯 영역이 모두 완료될 때까지 기다리는 방식이 아니며, 결과가 하나 이상 있으면 문서를 만들 수 있습니다.

  1. 영역별 생성 결과결과가 있는 영역 선택
  2. 최종 문서 요청프로젝트 설명과 함께 입력
  3. Markdown 출력한 문서로 정리
handle_finalize · 최종 문서 ↗

세션은 메모리에 저장되며 연결 종료 시 삭제됩니다. 실패한 수정 뒤에는 이전 생성 결과가 남습니다. 공개 실행 코드는 영역별 상태 관리이며 LangGraph 그래프 실행은 포함하지 않습니다.
