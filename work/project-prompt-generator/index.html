6개 설계 영역

UI/UX, 시스템 아키텍처, DB, API, 배포, 테스트 6개 영역을 따로 논의한 뒤 하나의 Markdown 문서로 합쳐줍니다.

FastAPI로 세션 상태를 관리하고, LangChain을 통해 Solar Pro를 호출합니다.

영역별 대화 문맥

LLM을 호출할 때마다 해당 영역의 지침, 프로젝트 설명, 그 영역의 이전 대화만 묶어 보내 API 논의와 UI 질문이 서로 섞이지 않게 분리했습니다.

초기 질문 생성은 asyncio.gather로 병렬 처리했고, 동기식 LLM 호출은 asyncio.to_thread로 넘겨 WebSocket 이벤트 루프가 막히지 않게 했습니다.

완료 조건과 오류 복구

영역별 대화가 시작되면 상태를 in_progress로 바꾸고, 최소 3라운드 이상 대화가 오간 뒤 모델 응답에 [GENERATE_PROMPT] 태그가 포함됐을 때만 결과를 확정(completed)하도록 했습니다.

LLM 호출이나 파싱 과정에서 예외가 나면 라운드와 상태를 직전(pending)으로 되돌려, 실패한 응답이 대화 히스토리에 오염되지 않게 막았습니다.

  1. pending입력 대기
  2. in_progressround + 1 · 모델 호출
  3. completedround ≥ 3 + 완료 태그

미완료 응답 → in_progress 유지 · 예외 발생 시 → pending·이전 라운드 복구

Markdown 문서 생성

6개 영역을 전부 끝낼 필요 없이, generated_prompt가 하나 이상 만들어진 시점부터 완료된 영역만 모아 프로젝트 설명과 함께 하나의 Markdown 문서로 정리해 줍니다.

  1. 영역별 생성 결과결과가 있는 영역 선택
  2. 최종 문서 요청프로젝트 설명과 함께 입력
  3. Markdown 출력한 문서로 정리
handle_finalize · 최종 문서 ↗

현재는 인메모리 세션이라 연결이 끊기면 대화가 초기화됩니다. 수정 요청이 실패하면 기존 결과를 유지하며, 공개 코드는 LangGraph 대신 직접 구현한 영역별 상태 관리 로직으로 동작합니다.
